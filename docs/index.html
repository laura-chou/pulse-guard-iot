1. Firmware: Dual-Core Real-time Scheduling & Power Optimization 1. 韌體端：雙核即時調度與功耗優化

Based on the ESP32 and FreeRTOS real-time operating system, the firmware adopts a dual-core thread isolation architecture to ensure physiological signal capture is free from network communication and peripheral latency. 基於 ESP32 與 FreeRTOS 即時作業系統，採行雙核執行緒隔離架構，確保生理訊號捕捉不受網路通訊與周邊延遲干擾：

  • Dual-Core Task Scheduling:雙核任務調度： Core 1 is dedicated to high-frequency physiological signal sampling, dual filtering (DC/MA), dynamic TFT screen refresh, and button detection. Core 0 is independently responsible for Wi-Fi maintenance and TLS/SSL encrypted communication, utilizing thread-safe queues for inter-core data transmission. Core 1 專職執行高頻生理訊號採樣、雙重濾波（DC/MA）、TFT 螢幕動態刷新與按鍵偵測；Core 0 則獨立負責 Wi-Fi 連線維護與 TLS/SSL 加密通訊，並透過執行緒安全的佇列（Queue）進行雙核間的數據傳輸。
  • Intelligent Measurement & Alarm Logic:智慧量測與警報邏輯： Features a built-in 60-second measurement cycle with the first 5 seconds as the signal stabilization period. SpO2 is calculated using an empirical formula based on the R/IR ratio. The system implements a "Three-Level Dynamic Alarm" (Danger/Warning/Normal) based on SpO2 and heart rate, using non-blocking time-difference control for the buzzer throughout the system to prevent traditional delay-induced sampling stalls. 系統內建 60 秒量測機制，前 5 秒為信號穩定收斂期。血氧採紅光與紅外光比值之經驗公式計算。系統依據血氧與心率指標實施「三級動態警報」（危險/警告/正常），並全機採用非阻塞式時間差控制蜂鳴器，避免傳統延遲卡死採樣。
  • Power Saving & Robustness:省電與防呆機制： Includes "Finger-off Detection" that resets the timer when no signal is detected. If the sensor remains idle for too long, the system automatically enters Deep Sleep to conserve power, supporting wake-up via button interrupt. The button also supports long-press reset, clearing system queues and sending a reset notification to the cloud via MQTT. 具備「離手偵測」功能，當感測器無訊號時重置計時；若維持離手狀態過久，系統自動進入深層睡眠（Deep Sleep）以節省功耗，並支援按鍵中斷喚醒。此外，按鍵亦支援長按重置功能，同步清空系統佇列並對雲端 MQTT 發送重置通知。

2. Backend: Stream Processing & Intelligent Analysis 2. 後端：串流處理與智慧分析

The Python backend serves as the system brain, responsible for receiving MQTT physiological data streams, performing real-time noise reduction, measurement lifecycle management, and multi-dimensional health assessment: Python 後端作為系統大腦，負責接收 MQTT 生理數據串流，進行即時降噪、量測生命週期管理與多維度健康狀態判定：

  • Data Cleaning & Source Isolation:資料清洗與來源隔離： Automatically distinguishes and labels Production and Test data via MQTT topics. Performs real-time integrity checks; if sensor detachment (OFF-CHIP) or invalid values are detected, data is discarded to avoid polluting the processing window. 透過 MQTT Topic 自動區分並標記正式（Production）與測試（Test）數據。系統即時檢查數據完整性，若偵測到感測器脫落（OFF-CHIP）或數值不合法，將直接捨棄該筆資料，避免污染後續的運算視窗。
  • EMA Noise Reduction & Analytics:時序指標運算與 EMA 降噪： Combines MA and EMA for dual smoothing. Utilizes collections.deque(maxlen=15) for a 15-point window and applies a fixed weight (α = 0.3) for EMA to capture trends. Calculates the absolute difference (Delta) between current heart rate and window average for sudden abnormality analysis. 結合滑動平均（MA）與指數移動平均（EMA）進行雙重平滑。利用 collections.deque(maxlen=15) 維持 15 筆時序視窗計算平均值，並採用固定權重（α = 0.3）計算 EMA 以捕捉長期趨勢。同步計算當前心率與視窗平均的絕對差值（Delta），作為突發異常的分析依據。
  • Health Evaluation & Reporting:雙軌制健康評估與報告生成： Integrates "Real-time Threshold Monitoring" and "Interval Trend Analysis" to differentiate transient anomalies from long-term risks. Automatically generates structured LINE Flex Message reports at the end of a session (Production only). 結合「單點即時閾值監控」與「區間趨勢統計分析」，精準區分短暫的突發性異常與長期的持續性風險。於動態量測生命週期（Session）結束時，系統自動將評估結果轉譯為專業的 LINE Flex Message 結構化報告，即時推送至使用者手機（僅限正式環境）。
  • Intelligent DB Persistence Strategy:智慧型資料庫持久化策略： Balances real-time alerts and MongoDB write load via event-driven and heartbeat strategies. Writes data on "First valid data," "DANGER status," "State transition," or "20-second interval." Includes fault tolerance with automatic retries if disconnected. 為平衡即時警報需求並降低 MongoDB 寫入壓力，系統採事件驅動結合定時心跳策略。僅在「首筆有效資料」、「危險狀態（DANGER）」、「狀態轉換」或「間隔滿 20 秒」時執行寫入。具備斷線容錯機制，寫入成功後才更新狀態指標，若斷線則於下一秒自動重試，確保數據不漏失。
  • Dynamic Session Management:動態生命週期（Session）管理： Generates unique UUIDs upon first valid data. COMPLETED status triggers reporting and cache clearing. Hardware RESET marks interruptions in the database and resets all session states. 收到首筆有效數據時動態生成 UUID 唯一識別碼。當量測正常結束（COMPLETED）時，觸發報告模組並清空全域快取；若接收到硬體端長按觸發的系統重置（RESET），則於資料庫標記異常中斷，並同步完成快取清空與狀態重置。

3. Analytics: Data Visualization & Insights 3. 分析端：數據視覺化與洞察

The Streamlit-based dashboard provides a powerful interface for reviewing historical trends and system performance: 基於 Streamlit 的分析看板為使用者與開發者提供了強大的介面，用於回溯歷史趨勢與系統表現：

  • Multi-Environment & i18n Support:多環境與雙語系切換： Supports dynamic environment switching (?env=test) and full i18n support for Traditional Chinese and English via URL parameters. 支援 URL 動態參數解析，可透過 ?env=test 無縫切換資料庫來源以隔離測試數據；同步整合 i18n 模組，支援經由 ?lang= 參數動態切換介面。
  • High-Availability DB Integration:高可用資料庫整合與容錯： Features built-in automatic degradation; redirects to Mock Data if MongoDB is unreachable, ensuring UI availability. 透過 pymongo 連接 MongoDB 叢集。內建自動降級與容錯機制，若遇資料庫連線失敗，系統將導向「模擬測試數據（Mock Data）」，確保前端 UI 高可用性。
  • Multi-Dimensional Aggregation:多維度資料預處理與聚合： Implements dual logic: daily summaries for long-term trends and hourly deduplication prioritizing critical events (DANGER > WARNING > NORMAL). 設計雙重聚合邏輯，按日統計心率極值與血氧最低值走勢；並按小時去重，依嚴重程度優先級（DANGER > WARNING > NORMAL）保留關鍵事件。
  • Interactive Time-Series Charts:時序指標監控與雙軸圖表： Leverages Plotly for multi-axis physiological trend charts, including 90% SpO2 danger baselines and health status distribution. 整合 Plotly 繪製多軸生理趨勢圖，將心率區間以填充色呈現，並標記 90% 血氧危險紅線。另搭配圓餅圖直觀呈現健康狀態佔比。
  • Advanced Log Rendering:進階異常日誌檢索與渲染： Utilizes st_aggrid with dynamic conditional rendering via JavaScript to highlight high-risk events (DANGER/WARNING). 導入 st_aggrid 元件。透過注入 JavaScript 實作動態條件渲染，根據健康狀態（DANGER / WARNING）即時改變背景顏色。
